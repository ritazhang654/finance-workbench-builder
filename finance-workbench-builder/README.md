# Finance Workbench Builder

构建企业级财务 / 业务管理工作台的 Agent Skill——一套经过真实项目完整验证的方法论，供 AI 编码助手按图施工，把「多模块业务系统」的搭建变成可复制的流水线。

## 这是什么

本仓库是一个 [Agent Skill](https://github.com/anthropics/skills)（SKILL.md 格式），沉淀自一个真实交付的酒店集团运营工作台：

- **16 个导航模块、16 张数据库表**，前后端各约 2000 行
- 技术栈：NestJS + Drizzle ORM + PostgreSQL（后端）、React 19 + TailwindCSS + antd-table（前端）、飞书多维表格同步与消息提醒（自动化）

### 覆盖的模块形态

| 域 | 模块 | 可复用的核心形态 |
|---|---|---|
| 财务资金域 | 财务总览、费用报销、付款申请、发票管理、预算管理、S 账、AR 账、异常操作监控、OTA 对账 | 审批流、唯一单证、阈值预警、账龄分桶、主从核对结算 |
| 运营域 | 门店档案、能耗抄表、单房成本模型与分析、集团看板 | 主数据批量建档、外部数据源同步、定时提醒推送、公式引擎 + 报表导入 |
| 权限治理 | 角色成员管理、页面权限配置 | 「角色 × 页面」可配置矩阵、平台角色 SDK 封装 |

## 适用场景

用户（或你自己）要让 AI 搭建以下任何一类系统时，加载本 skill：

- 财务工作台、资金管理、对账系统、报销审批、付款申请
- 发票管理、预算控制、账龄管理、异常操作监控、经营数据看板
- 门店档案管理、能耗抄表、单房成本分析、GOP 报表导入
- 角色权限管理、页面权限配置
- 任何「多模块 + 数据表格 + 状态流转 + 风险预警」形态的企业业务系统

即使用户只说「做个管理系统」「搭个工作台」「把这几张表管理起来」，也适用。

## 使用方式

### 妙搭 / 支持技能目录的平台

把 `skills/finance-workbench-builder/` 整个目录放入技能目录，skill 会按 description 中的触发词自动召回。

### Claude Code / 其他 Agent CLI

复制到项目的 skills 目录（如 `.claude/skills/`），或在提示词中指向 `SKILL.md`。

### 技能结构

```
finance-workbench-builder/
├── SKILL.md                          # 主方法论：总体架构、八步搭建流程、常见坑、检查单
├── README.md
└── references/
    ├── module-catalog.md             # 13 个模块条目：表结构、端点清单、页面要点
    ├── backend-patterns.md           # 后端三文件骨架、状态机、分页、Drizzle 易错点
    ├── frontend-patterns.md          # 前端四文件拆分、表格/弹窗/表单模式、路由导航
    ├── design-tokens.md              # 「冷峻商务蓝 + Grid 网格」设计系统 token 对照
    ├── import-automation.md          # Excel 报表导入、多维表格同步、飞书提醒自动化
    └── rbac-matrix.md                # 可配置页面权限矩阵、平台角色 SDK、常见陷阱
```

## 方法论要点

- **数据流单向**：DDL 建表 → 生成 schema → 共享类型契约 → 后端模块 → 聚合文件预填 → 前端页面 → 测试验收，任何一步跳过都会在下一步还债
- **模块同构复用**：先在模块目录里找同构模板，替换领域字段即可复用整套骨架
- **契约先行**：`shared/api.interface.ts` 是前后端唯一事实，先写类型再写实现
- **风控内建**：金额一律 numeric、状态机设防、导入防重复建档、警示色克制使用

## 验证声明

方法论在一个生产在用的酒店集团工作台上完整验证：财务审批与对账链路、80+ 门店档案批量导入、每日能耗抄表同步与飞书提醒自动化（连续多日稳定执行）、多角色权限矩阵均为线上运行代码的沉淀，非理论设计。
